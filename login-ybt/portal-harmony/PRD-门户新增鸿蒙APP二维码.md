## 1. 背景与目标

### 1.1 背景

1. 桂教通 APP 已完成鸿蒙原生版本（HarmonyOS NEXT）开发，并已在华为应用市场上架，但门户右侧「下载客户端」面板仅提供 **微信小程序、Android、iOS** 三个入口，鸿蒙用户到达门户后**无下载路径**。
2. 鸿蒙设备（尤其教育系统集采的华为 MatePad / Mate 系列）在教师群体中占比持续上升，客服与学校管理员侧已出现「鸿蒙手机装不了 APP」的咨询。
3. 鸿蒙与 Android 的安装链路不同：**不能直接安装 APK，需经华为应用市场（AppGallery）**。因此浮层必须写清「用鸿蒙手机扫码」，并由二维码背后的短链承担设备识别与降级——**门户内不再堆叠多步安装教程**，避免把一次扫码变成一份说明书。

### 1.2 目标

| 类型 | 指标 | 现状 | 目标（上线 1 个月） |
| --- | --- | --- | --- |
| 业务 | 鸿蒙端下载转化率（扫码 → 安装完成） | — | ≥ 55% |
| 业务 | 鸿蒙二维码日均扫码量 | 0 | ≥ 300 |
| 体验 | 因「装不上 APP」产生的客服工单 | 约 12 单/周 | 下降 70% |
| 体验 | 扫码后 30s 内到达应用市场的比例 | — | ≥ 80% |

### 1.3 非目标（本期不做）

- 不做鸿蒙端的应用内更新能力（依赖华为应用市场统一推送）。
- 不做鸿蒙平板 / 鸿蒙 PC 的适配宣传（暂不支持）。
- **不做门户内的安装步骤指引**：本期浮层移除「安装指引」入口，只保留一个「复制链接」按钮（扫码装不上时复制短链发到手机浏览器打开即可）。
- 不改动 Android / iOS / 微信小程序 三个入口的既有逻辑与视觉。
- 钉钉、企微入口本期**从下载面板下线**（见 F2 说明），不属于新增能力。
- 不做下载统计看板（仅埋点上报，看板由数据组按需搭建）。

## 2. 用户与场景

| 角色 | 典型场景 | 核心诉求 |
| --- | --- | --- |
| 教师（个人） | 新换华为鸿蒙手机，在电脑上打开门户找 APP | 一眼看到「鸿蒙」入口，扫码即装 |
| 学校管理员 | 全校推广 APP，需要给老师发安装说明 | 一键复制下载链接，可直接转发 |
| 学生 / 家长 | 用鸿蒙手机访问门户 | 扫码后能顺利跳到应用市场 |
| 客服 / 运营 | 收到「装不上」工单 | 有标准话术与下载短链可用 |

## 3. 方案总览

### 3.1 信息架构（改动点）

```
PC 门户首页
├─ 右侧悬浮工具栏（下载 / 微信 / 帮助 / 客服 / 管理员）
│  └─ 【下载】展开「下载客户端」面板
│     ├─ 微信小程序
│     ├─ APP(Android版)二维码
│     ├─ APP(IOS版)二维码
│     └─ 鸿蒙APP二维码  ← 本次新增（第 4 项）
│        └─ 点击 → 二维码浮层（新增字段：系统要求 / 复制链接按钮）
│           └─ 浮层内只有一个蓝色主按钮「复制链接」（本期不提供安装指引）
└─ 顶栏右上角头像 → 账号气泡  ← 本次新增
   ├─ 身份信息（姓名 / 部门 / 手机掩码）
   └─ 动作：进入我的空间 / 智教通行证 / 可信认证（新增）/ 退出
```

### 3.2 主流程

```
用户进入门户
  → 鼠标悬停右侧「下载」图标（或点击）
  → 面板展开，展示 4 个客户端
  → 点击「鸿蒙APP二维码」
  → 浮层展示二维码 + 版本 + 系统要求 + 蓝色「复制链接」按钮
      ├─ 用鸿蒙手机扫码 → 跳华为应用市场 → 安装 → 登录  ✅ 主路径
      ├─ 装不上 / 想在手机浏览器里装 → 点「复制链接」→ 发到手机打开  ✅ 兜底路径
      └─ 非鸿蒙设备 → 点「下载 Android 版」切换浮层  ✅ 降级路径
```

## 4. 详细功能需求

### F1 悬浮工具栏入口

| 项 | 说明 |
| --- | --- |
| 位置 | 页面右侧固定悬浮，`position: fixed`；**距视口右侧 14px、距视口底部 250px**，随窗口缩放保持右下锚定 |
| 形态 | **白色独立胶囊卡片**（非贴边条）：宽 66px、圆角 16px、1px `#E8EEFA` 描边、四面投影 `0 10px 34px rgba(18,45,110,.13)`；顶部/底部各一条 20×3px 短横线作拖拽把手暗示 |
| 图标规格 | 图标 21px（线性描边 2px）置于 36px 圆形浅色底内，标签 10.5px 置于图标下方；间距节奏：图标与标签 4px、按钮间 1px、按钮内边距 8/7px |
| 悬浮区主色 | `#2C8FEC`（悬浮工具栏、面板、二维码浮层内的全部蓝色统一为此色，不改动页面品牌蓝 `#1D4ED8`） |
| 图标配色 | 下载 `#2C8FEC`/`#E7F4FD`、微信 `#07C160`/`#E6F9EF`、帮助 `#F59A23`/`#FFF3E0`、客服 `#2C8FEC`/`#E7F4FD`（**实心耳机**，非线框）、管理员 `#2C8FEC`/`#E7F4FD`（**双色人像+齿轮**：人像浅蓝 `#BCDCFA` 填充 + 主色描边，齿轮主色实心）；**五个入口均需有色彩，不使用灰色单色图标**，仅在图标圆底上着色，不做整块彩色背景 |
| 图标顺序 | 下载 → 微信 → 帮助 → 客服 → ─ → 管理员（「帮助」落在微信与客服之间；**原「简/繁」位改为「管理员」**，切换语言的能力从工具栏移除） |
| 行为 | 悬停「下载」图标展开面板；移出面板 220ms 后收起；点击图标可锁定/取消锁定；**面板内已打开二维码时面板不自动收起** |
| 选中态 | 当前模块图标圆底加 `0 0 0 3px rgba(44,143,236,.18)` 光环，标签变 `#2C8FEC` 且加粗（500→600） |
| 悬停态 | 整个按钮铺 `#F0F8FE` 圆角底（12px），图标上浮 2px 并带 `0 6px 14px rgba(18,45,110,.12)` 投影；不做位移缩放以外的形变 |
| 新增提示 | 「下载」图标右上角红点（有新增端时展示，用户点击过后消失，7 天内不再出现），红点距图标右上角外侧 2px 白描边隔离 |
| 面板提示 | 面板标题右侧展示「点击查看二维码」，明确条目的点击语义（避免用户以为是纯展示列表） |
| 吸顶 | 面板随视口固定，页面滚动不跟随滚动 |
| 层级 | `z-index` 高于页面内容，低于弹窗与全局提示 |
| 矮屏兜底 | 视口高度 ≤ 820px 时底距降为 150px、≤ 620px 时降为 60px 并压缩按钮内边距，避免压住主导航（详见 F7） |

> 说明 1：本期**不新增**一级图标以外的结构改动，「鸿蒙」仍复用「下载」入口，不单独占一个图标位（工具栏 5 个图标、宽 66px 已是可读性上限，再加一个会挤压标签）。
>
> 说明 2：**帮助与管理员入口的定位**——「帮助」点击不弹浮层，直接 Toast「常见问题：请前往帮助中心」；「管理员」由原「简/繁」位改造而来，点击 Toast「管理员入口：请使用管理员账号登录管理后台」，承载门户内容维护/权限入口，避免管理员每次都要绕到个人中心。

### F2 客户端列表面板

| 序号 | 名称（展示文案） | 说明 |
| --- | --- | --- |
| 1 | 微信小程序 | 保持不变 |
| 2 | APP(Android版)二维码 | 保持不变 |
| 3 | APP(IOS版)二维码 | 保持不变 |
| 4 | **鸿蒙APP二维码**（新增） | 置于末尾；右侧带 `NEW` 标签 |

> **钉钉 / 企微本期下线**：两个入口的扫码安装量不足总下载量的 3%，且组织内用户已通过工作台免登进入，面板保留它们会让「鸿蒙」落到第 6 位、需要滚动才能看到。下线后鸿蒙升到第 4 项，一屏可见。配置项保留（`ding_enabled` / `wecom_enabled`），后续可随时恢复。

**规则：**

- R2-1 面板宽度 216px，行高 42px，图标 22px，文字 13px，与现有条目完全一致，**不因新增条目改变面板宽度**。
- R2-2 面板最大高度 = 视口高度 − 160px；超出时内部滚动（4 项固定，不触发）。
- R2-3 新增行的图标使用鸿蒙官方「HarmonyOS」单色标识，不得使用华为花瓣 LOGO（商标合规）。
- R2-4 `NEW` 标签：红底白字，字号 9.5px，展示周期默认 14 天，由后台开关控制（`harmony_new_badge`）。

### F3 鸿蒙二维码浮层

点击「鸿蒙APP二维码」后，在面板左侧弹出浮层（宽 296px），字段如下：

| 字段 | 示例 | 必填 | 规则 |
| --- | --- | --- | --- |
| 应用名 | 桂教通 · 鸿蒙版 | 是 | 固定文案 |
| 副标题 | HarmonyOS NEXT 原生应用 | 是 | 固定文案 |
| 角标 | 官方 | 是 | 绿色「官方」；与 NEW 标签并存时以 NEW 为主色 |
| 二维码 | 176×176（含白边） | 是 | 详见 F6 |
| 扫码提示 | 用鸿蒙手机「相机」扫码，跳转应用市场安装 | 是 | 首次出现必须写明「鸿蒙手机」 |
| 版本号 | v1.0.0 · 32.6MB | 是 | 由配置读取，避免发版 |
| 更新时间 | 2026-11-18 | 是 | 同上 |
| 系统要求 | HarmonyOS NEXT 5.0 及以上 | 是 | **高亮蓝色**，本条为硬性门槛 |
| 唯一按钮 | 复制链接 | 是 | **蓝色主按钮（`#2C8FEC`）占满浮层宽度**；复制下载短链到剪贴板并 Toast 提示；本期不提供「安装指引」入口 |
| 底部兜底 | 暂无鸿蒙设备？下载 Android 版 | 是 | 点击切换为 Android 版浮层 |

**交互规则（点击触发）：**

- R3-0 **采用「点击」而非「悬停」触发**：浮层位于面板左侧，悬停方案下用户从条目移向浮层的移动路径会离开面板命中区，浮层随即消失，导致二维码无法点击/长按（实测反馈问题）。故改为点击打开、点击关闭。
- R3-1 点击任一条目 → 浮层展开并**锁定**；鼠标移到浮层上时浮层与面板都不收起，可正常点击按钮、右键保存二维码。
- R3-2 收起方式有 4 种：再次点击同一条目、点击浮层右上角 `×`、点击页面空白处、按 `Esc`。
- R3-3 已锁定浮层时，面板不因鼠标移出而收起；浮层收起后，面板恢复「移出 220ms 自动收起」的原有行为。
- R3-4 同一时刻只允许一个浮层存在；点击其他条目时浮层内容原地替换（不重建，避免二维码闪烁）。
- R3-5 浮层不可超出视口左边界（`min-left: 16px`），小屏时改为**居中弹窗**展示（见 F7）。
- R3-6 浮层内所有可点击元素需 `cursor: pointer` 且有 hover 反馈；条目支持 `Enter` / `Space` 键盘触发。
- R3-7 二维码图片带 `alt`（"桂教通鸿蒙版下载二维码"），可长按/右键保存。

### F5 复制链接与降级

- R5-1「复制链接」复制短链 `https://app.guijiaotong.cn/hm`（示例），带渠道参数 `?ch=portal_harmony_qr`。
- R5-2 复制成功 Toast：「下载链接已复制，可发送到手机打开」，2s 消失。
- R5-3 复制失败（非 HTTPS 或浏览器不支持 Clipboard API）降级为 `document.execCommand('copy')`，仍失败则弹出手动复制的输入框。
- R5-4 底部「下载 Android 版」点击后：浮层原地切换为 Android 版内容，并上报 `switch_to_android` 事件。

### F6 二维码生成与渠道追踪

| 项 | 方案 |
| --- | --- |
| 二维码类型 | 静态短链二维码（长期有效），不做过期 |
| 生成方式 | 后台配置短链，前端由 `qrcode.js` 本地生成，避免第三方图片服务不可用 |
| 短链指向 | 华为应用市场详情页 DeepLink（`appmarket://details?id=xxx`），失败降级为 H5 落地页 |
| 渠道参数 | `ch=portal_harmony_qr`，用于区分门户 / 小程序 / 线下海报等来源 |
| 像素尺寸 | 生成 440×440，展示 176×176（2.5 倍图，保证扫码识别率） |
| 纠错等级 | H（30%），中心需叠加 LOGO |

**DeepLink 失败兜底（H5 落地页）：** 落地页需检测 UA，非鸿蒙设备展示「当前设备不是鸿蒙系统」+ 可选端列表；鸿蒙设备展示「打开应用市场」按钮 + 手动搜索图文。

## 13. 附录：研发接入说明

### 13.1 数据结构

```js
{
  id: "harmony",
  name: "鸿蒙APP二维码",
  icon: "harmony",              // 单色 svg symbol
  title: "桂教通 · 鸿蒙版",
  sub: "HarmonyOS NEXT 原生应用",
  qrUrl: "https://app.guijiaotong.cn/hm?ch=portal_harmony_qr",
  version: "v1.0.0",
  pkgSize: "32.6MB",
  updatedAt: "2026-11-18",
  minOs: "HarmonyOS NEXT 5.0 及以上",
  isNew: true,
  guide: true
}
```

### 13.2 关键实现要点

1. **二维码本地生成**：使用 `qrcode` 库生成 440px canvas，纠错等级 H；中心 LOGO 用绝对定位叠加，不做图片合成，便于换色。
2. **浮层与面板的 hover 链路**：面板 `mouseenter` 时清除收起定时器，`mouseleave` 时启动 220ms 定时器；浮层自身 `mouseenter` 同样清除定时器，否则用户无法点击浮层按钮。
3. **弹窗焦点管理**：打开时记录 `document.activeElement`，关闭后 `focus()` 还原；弹窗内需实现 Tab 循环（焦点陷阱）。
4. **配置下发**：与现有五个端共用同一份 `clientList` 配置，新增 `harmony` 节点，前端按数组顺序渲染，不做硬编码顺序。
5. **埋点上报**：统一走现有 `track()` 方法，事件名遵循 `portal_{module}_{action}` 规范。
